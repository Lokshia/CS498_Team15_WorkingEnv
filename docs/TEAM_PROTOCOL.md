# 团队协议 · v0.4.0 / forearms-contact-v1

## 1. 研究任务与边界

箱子起初放在两条前臂上，无 CONNECT/WELD、绑带或固定平台。研究如何通过
22 个关节动作保持机器人与箱体稳定，允许修正步；不研究从地面拾取或手指抓取。
这是团队研究起点，不是已经训练成功的策略或真机控制器。

原 proposal 的“双腕柔性连接”与此任务不同。团队应在报告中说明改成自由接触
承托，增加防滑落要求。旧 pregrasp 保留在 `configs/pregrasp_protocol.json`，
必须显式选择 `--support-mode pregrasp`；不能合并两种模式的成功率。

## 2. 前臂承托、失败与成功

机器可读协议为 `configs/team_protocol.json`。本版约定如下：

- `payload_forearm_supported`：箱子同时接触左右指定前臂碰撞体，且两侧
  对箱子的世界竖直向上合力分别大于 1e-6 N。不是依据手/箱参考点距离推断。
  这证明当前采样有双侧向上接触，不代表两臂平均分担全部重力或达到静力平衡。
- 左右前臂末端球形碰撞体允许辅助接触，但不计入上述有效承托；只靠末端球
  支撑仍会累积失去前臂承托的步数。箱子接触地面或除此以外的机器人碰撞体
  立即判失败。禁止靠胸、腿等支撑绕过任务，这是本版实验约定。
- 失去双侧承托允许连续最多 6 个控制步（0.12 s）；第 7 步仍不满足则失败。
  从第 1 步开始计数，不另外叠加初始宽限期。恢复双侧承托后计数归零。
  这容许初始 1 微米间隙闭合和短暂接触波动，不将长时间抛箱算成功。
- 机器人基座低于 0.28 m、倾斜超过 60°、箱体中心低于 0.20 m、数值非有限，
  同样失败。正常达到时间上限不算跌倒。
- 成功必须完整经历 **20 s / 1,000 控制步**，无上述失败；每个记录步箱体倾角
  **严格小于 10°**、相对初始目标高度的绝对误差**严格小于 0.05 m**。
  高度/倾角从第 1 步检查，没有宽限期，不能用均值代替最大误差。

这些条件按仿真控制步采样，不是连续时间物理证明。传感器取 pinned mjlab
控制步内末个物理子步的接触信号，训练终止和评测共用同一快照/计数。
批次中已失败或已完成的 episode 统计被冻结；为其他槽位继续运行而重置仿真
不会把旧失败改成成功。`valid_hold` 仅是瞬时诊断，不是 episode 成功率。

## 3. 公平训练和评测

| 设置 | 团队约定 |
|---|---|
| 训练质量占模型空载质量比例 | 0%、2.5%、5%，顺序固定质量课程 |
| 留出插值负载 | 1.25%、3.75% |
| 压力测试 | 7.5%，单独报告 |
| 独立训练 seed | 11、22、33 |
| 配对评测 seed | 1011、1022、1033 |
| 每个 checkpoint | 每种负载 50 episodes，共 150 episodes |
| 三个独立 seed / 每种策略类型 | 共 450 episodes |
| 正式评测批量 | 每位成员统一 `--num-envs 32`，最后一批 18 |
| 对照策略 | mass-conditioned 与 mass-blind，其他设置和 transitions 相同 |

质量比例基于模型实测机器人质量，约 19.7969 kg。0% 是 1 g 正惯量代理，
并不是移除箱体。不同重量构建新环境，质量、惯量一起重新编译。

`--iterations` 是每个课程阶段的 PPO 更新数；每迭代默认采样 24 步/环境。
环境数 × rollout 步数 × 更新数才是采样预算，训练分钟数不能替代。课程阶段
延续模型、观测归一化和优化器。`--resume` 保留原训练 seed；不能换 seed
把续训伪装为独立重复。三阶段 curriculum 每次调用都从第一个质量阶段开始，
如果只想续训最后负载，用 `--mass-fraction 0.05 --resume ...`，不要再加课程。
续训不恢复 RNG 或完整物理状态，不保证从中断处逐位重放。

质量盲对照仅把观测第 94 项（质量比例）设零，actor/critic 都如此；物理质量
不变，其他动力学特征仍可隐式反映负载。评测和回放盲策略也加 `--mass-blind`。

seed 从 checkpoint 的相邻 `experiment.json` 读取，优先于评测 CLI `--seed`。
无 checkpoint 是明确标注的零动作 PD 基线。每批使用评测 seed + episode offset；
环境数影响随机流，因此不要混用不同批量的结果。成员姓名标签不改变 seed/物理。

`--quick` 只测 3 负载 × 2 episodes × 2 秒，共 6 次，仅检查流程。
80% 是 proposal 目标，不是当前完成结果。不要删除失败、只报最好 seed，
或用 viewer 的一段视频替代完整评测。

## 4. 队友共享与实验记录

四人使用同一 Git commit/发行 ZIP、`uv.lock` 和协议 hash。不自行升级依赖。
保留 checkpoint 与其 `experiment.json`、`completed.json`、逐 episode 结果、
设备/驱动、源码指纹、模式、任务/观测 schema 和实际训练步数。

checkpoint 校验模式、schema、质量观测类型与 seed；不同任务不能因为维度
相同而互载。权重加载是可信代码路径，只加载自己或可信队友生成的文件。
改物理/奖励/判据仍须团队审查、更新任务版本；schema 不是替代源码核对的工具。

四人复测同一个 checkpoint 用 `scripts/compare_results.py` 检查配置；该工具
故意拒绝不同 checkpoint，不用于比较两个策略谁更好。策略比较应看各负载
`condition_summaries` 和逐 episode 记录，插值与压力测试分开。

`team_protocol.json` 仍是**无外力扰动、固定质量**的基线评测。训练可以按
`README` 第 3 节加上按环境的质量/重心随机化、箱子位姿抖动和推力；这些不改
判据和 `task_schema`，但必须在报告里写明训练范围。带推力的评测用
`configs/team_protocol_push.json`（`k1-forearms-contact-v1-push`：判据、
负载、seed、episode 数与基线相同，另加每 3–5 s 一次、每轴 ±0.3 m/s 的基座速度
踢），成功率与基线分开列，不能合并，也不能只报有利的一种。重心偏移评测需
另建带 `randomization.payload_com_offset_m` 的版本化协议。不同硬件不承诺逐位
一致。仿真成功不证明真机安全，见 `SIM_TO_REAL_ZH.md`。

## 5. 开发验证与正式实验分开

运行 `scripts/check_training.py --device cuda` 做少量迭代验收；它会验证保存、
恢复、课程、质量盲对照、快速评测和 CPU 推理，生成 `acceptance.json`。
产物留在本地 outputs，不进入源码 ZIP；小测试策略不是团队研究成果。
初次正式训练前建议再做 30–60 分钟 pilot，测环境数、吞吐、内存和学习趋势。
尚未标定的奖励权重、接触摩擦、宽限期均是可研究参数，不是最优配置。
